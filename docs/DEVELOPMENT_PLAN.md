# Source Insight 风格 VS Code 代码阅读插件：需求与开发计划

版本：0.1（需求草案）
日期：2026-10-18
当前阶段：需求设计，尚未进入实现。

> 本文件保留最初的需求基线。现已迭代至 0.2.0，实际完成范围和未验收项以 [0.2 验证报告](VALIDATION_0.2.md) 为准。

## 1. 目标与范围

在 VS Code 中提供接近 Source Insight 的连续代码阅读体验，围绕以下五项能力构建统一工作流：

1. 函数列表窗口（Symbol Window）。
2. 文件树窗口（Project Window）。
3. 上下文预览窗口（Context Window）。
4. 符号关系窗口（Relation Window）。
5. 引用查询（Lookup References）。

核心目标是：用户保持主阅读位置，通过辅助窗口查看定义、调用关系和引用现场，决定深入时再跳转，并能返回原来的阅读位置。

借鉴 Source Insight 的信息组织与联动方式，不要求逐像素复刻其界面。本文区分 Source Insight 已有设计、建议实现的交互，以及需要验证的 VS Code 平台能力。

### 1.1 初始工作假设

- 第一阶段优先验证 C/C++，使用已有语言服务提供语义数据。
- 第一阶段选定一种 C/C++ 语言服务作为验收基线；候选为 clangd 和微软 C/C++ 扩展，实际支持范围通过技术验证确定。
- 架构保留其他语言接入能力，但首版不承诺所有语言达到相同效果。
- 第一阶段支持本地、单根工作区；多根工作区和 Remote/WSL 在后续阶段验证。
- 不自行开发完整 C/C++ 解析器，不要求工程能够成功编译，但语义分析可能需要正确的头文件路径、宏和编译数据库配置。
- 不修改源码内容，不把 AI 服务或外部网络服务作为基础功能依赖。

这些是开发计划的暂定边界，不代表用户已经指定了语言、后端或平台。

### 1.2 非首版范围

- 完整的图形调用图编辑器、任意节点布局。
- 精确的跨过程数据流分析、运行时调用链分析。
- 对函数指针、虚调用、回调和动态分派提供完整调用目标集合的保证。
- 独立解析器、全工程语义数据库、远程云索引。
- 重构、智能改名、代码生成和调试器集成。
- Source Insight 的富文本代码排版复刻。

## 2. Source Insight 设计映射

| 功能 | 借鉴的设计 | 插件中的目标 |
| --- | --- | --- |
| 函数列表 | 当前文件的符号入口 | 快速了解文件结构，按符号导航 |
| 文件树 | 工程文件入口 | 在纳入阅读范围的源码中定位文件 |
| Context | 跟随选择，自动呈现定义或上下文 | 尽量避免为短暂查看而离开主阅读位置 |
| Relation | 围绕当前符号展示关系，可持续展开 | 上下追踪调用链，保持分析根节点 |
| Lookup References | 查询符号的使用位置 | 查看完整引用现场，并保留查询结果 |

区别必须在产品中保持清晰：调用关系描述符号之间的边；引用结果描述具体源码位置。一个调用者调用同一函数三次，可以表现为一条关系和三个调用位置，但引用列表不能丢失这三个位置。

## 3. 界面与阅读模型

### 3.1 建议布局

```text
┌──────────────────┬─────────────────────────────┐
│ 代码阅读侧栏      │ 主编辑器                     │
│ ├ 文件树          │ 当前阅读文件                 │
│ ├ 函数列表        │                             │
│ └ Relation       ├─────────────────────────────┤
│                  │ Context                     │
│                  │ 定义预览 / 引用现场           │
├──────────────────┴─────────────────────────────┤
│ Lookup References：按文件分组的引用结果          │
└────────────────────────────────────────────────┘
```

以上为目标信息布局，不承诺插件能强制设置用户的编辑器布局。侧栏、面板位置和 Context 宿主方式应遵循 VS Code 可用能力，并允许用户调整。

### 3.2 主阅读位置与辅助预览

- 主阅读位置由文件 URI、光标位置、选择范围组成。
- Context 中的预览不能自动成为新的主阅读位置。
- 文件树“打开”、函数列表“定位”、关系或引用结果“跳转”可以显式改变主阅读位置。
- 选择关系节点或引用结果只更新预览；显式执行打开命令时才改变主编辑器。
- 主编辑器改变后，函数列表跟随主文件；Relation 是否跟随取决于其锁定状态。

### 3.3 统一联动规则

| 事件 | 函数列表 | Context | Relation | 引用结果 |
| --- | --- | --- | --- | --- |
| 主编辑器切换文件 | 更新列表并定位当前符号 | 自动模式下更新 | 未锁定时更新根节点 | 保持 |
| 主编辑器移动光标 | 高亮包含光标的函数 | 自动模式下预览定义 | 未锁定时更新，避免重复请求 | 保持 |
| 函数列表单击符号 | 选中并定位主编辑器 | 自动模式下预览定义 | 未锁定时更新 | 保持 |
| 选中关系节点 | 保持 | 未锁定时预览节点定义 | 保持当前关系树 | 保持 |
| 选中具体调用位置 | 保持 | 未锁定时预览调用现场 | 保持 | 保持 |
| 选中引用结果 | 保持 | 未锁定时预览引用现场 | 保持 | 选中该结果 |
| 在 Context 中移动光标 | 保持 | 保持，不发起递归跟随 | 保持 | 保持 |
| 显式打开预览位置 | 跟随新的主文件 | 按当前模式处理 | 按锁定状态处理 | 保持 |

“自动模式”表示 Context 未锁定且自动跟随已开启。任何新事件都不得绕过锁定状态；手动刷新可以更新锁定目标的内容，但不能偷偷切换目标。

## 4. 详细功能需求

优先级：P0 为首个可用版本必需；P1 为完整阅读体验所需；P2 为增强能力。

### 4.1 函数列表窗口

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FN-01 | P0 | 展示主文件的函数、方法及所属类或命名空间；支持层级符号和扁平符号数据 |
| FN-02 | P0 | 默认按源码位置排序，可切换按名称排序 |
| FN-03 | P0 | 单击定位到符号声明名称或签名位置，并聚焦主编辑器 |
| FN-04 | P0 | 主光标移动时选中最内层包含它的函数；不强制夺取列表焦点 |
| FN-05 | P0 | 按名称过滤；过滤只影响列表展示，不改变主文件 |
| FN-06 | P0 | 文件保存或编辑稳定后刷新，避免每次按键都重建列表 |
| FN-07 | P0 | 区分加载中、无函数、语言服务不支持和查询失败 |
| FN-08 | P1 | 可切换显示类型、变量、宏等其他符号；只展示后端实际提供的种类 |
| FN-09 | P1 | 从符号菜单执行定义预览、查找引用、设为关系根节点 |
| FN-10 | P1 | 显示后端提供的签名信息；无法获取时只显示名称，不推测签名 |

验收：切换两个文件后列表正确更新；重载函数能按位置分别定位；快速切换文件时不会显示旧请求返回的符号；光标在函数外时不误选上一个函数。

### 4.2 文件树窗口

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FILE-01 | P0 | 提供独立阅读文件树，按工作区目录组织文件 |
| FILE-02 | P0 | 点击文件在主编辑器打开；提供“在 Context 预览”独立命令 |
| FILE-03 | P0 | 遵循明确的包含、排除规则，支持源码扩展名和目录过滤 |
| FILE-04 | P0 | 懒加载目录，监听文件新增、删除、重命名并局部刷新 |
| FILE-05 | P0 | 提供刷新和定位当前主文件命令 |
| FILE-06 | P0 | 无工作区时显示引导信息，不把根目录作为默认扫描范围 |
| FILE-07 | P1 | 支持快速按文件名查找，重名文件显示相对路径 |
| FILE-08 | P1 | 支持多根工作区，每个工作区作为独立根节点 |
| FILE-09 | P1 | 可配置跟随当前主文件，保留用户展开状态 |
| FILE-10 | P2 | 工程阅读范围配置，支持只纳入指定目录或文件集合 |

配置策略：默认尊重 `files.exclude`，可选择额外使用 `search.exclude`；插件自己的包含、排除配置需明确优先级，不默认承诺自动遵循所有忽略文件。

验收：排除目录不可见；创建、重命名、删除文件后树正确更新；大目录展开不会先读取整个工程；预览文件不会改变主阅读位置。

### 4.3 Context 窗口

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| CTX-01 | P0 | 提供持续存在、可恢复的预览区域 |
| CTX-02 | P0 | 主光标停留在标识符后，自动查询并预览定义 |
| CTX-03 | P0 | 展示文件路径、符号名称、行号及目标附近源码，高亮目标范围 |
| CTX-04 | P0 | 关系节点、调用位置和引用结果可以向同一窗口发送预览目标 |
| CTX-05 | P0 | 支持锁定、解锁、手动刷新和在主编辑器打开 |
| CTX-06 | P0 | 多个定义时提供候选选择，显示路径，不静默选择不确定目标 |
| CTX-07 | P0 | 加载新目标时明确状态；失败后不能把旧代码伪装为新目标 |
| CTX-08 | P0 | 自动跟随采用防抖、取消和结果版本检查，不抢焦点 |
| CTX-09 | P1 | 提供定义、类型定义两种查询动作；类型定义不支持时给出明确状态 |
| CTX-10 | P1 | 支持查看包含函数或类型，作为显式模式而非混入定义匹配结果 |
| CTX-11 | P1 | 保留有限的预览前进、后退历史，独立于主阅读历史 |
| CTX-12 | P1 | 正确预览未保存缓冲区内容；底层文档变化后更新预览 |

宿主方案必须先验证：

- 原生编辑器分栏可复用语法高亮、选择和复制，但需要验证分组、焦点、标签和主编辑器识别的稳定性。
- Webview 可以提供固定的只读代码区域和明确控制栏，但需要实现代码显示、主题、行号、复制及安全渲染。
- 第一阶段只选定一种方案；不同时维护两套预览实现。

验收：主光标连续经过 A、B、C，最终只展示 C 的结果；锁定后其他窗口的自动选择不覆盖预览；选中引用结果显示使用位置而非符号定义；整个过程主编辑器位置和焦点保持稳定。

### 4.4 Relation 窗口

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| REL-01 | P0 | 从主光标或列表符号建立关系根节点，根节点显示名称与位置 |
| REL-02 | P0 | 支持 Incoming Calls（谁调用它）和 Outgoing Calls（它调用谁） |
| REL-03 | P0 | 按节点展开时懒查询下一层，不默认递归整个工程 |
| REL-04 | P0 | 提供自动跟随、锁定根节点、刷新和重新设根动作 |
| REL-05 | P0 | 选择函数节点预览定义；显式打开才跳转主编辑器 |
| REL-06 | P0 | 同一调用边保留多个调用位置，可展开或选择具体调用现场 |
| REL-07 | P0 | 区分不支持调用层次、无调用、失败和结果过期 |
| REL-08 | P0 | 对直接递归、间接递归标记路径内循环，避免无限自动展开 |
| REL-09 | P1 | 切换方向后保留根节点；展开状态按根节点和方向分别管理 |
| REL-10 | P1 | 源码修改后标记关系可能过期，允许刷新，不静默保留失效位置 |
| REL-11 | P1 | 实现类型继承、成员关系前先进行后端能力验证，分别标注支持状态 |
| REL-12 | P2 | 支持多个固定关系根节点或多个关系实例 |

技术语义约束：调用层次返回的调用位置通常属于调用者文件，不能直接按被调用者 URI 打开；必须在适配层归一化位置。Incoming 与 Outgoing 的位置归属分别验证。

验收：对 A → B → C 能逐层向下展开，也能从 C 向上展开；A → A 与 A → B → A 不导致无限展开；同一函数内两次调用保留两个位置；无法解析的间接调用不显示为已完整分析。

### 4.5 Lookup References

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| REF-01 | P0 | 从主编辑器、函数列表或关系节点显式发起引用查询 |
| REF-02 | P0 | 标题保留被查询符号、源位置及结果数量 |
| REF-03 | P0 | 默认按文件分组，每项显示行号、源码片段及匹配位置 |
| REF-04 | P0 | 选择结果在 Context 预览引用现场；显式打开定位主编辑器 |
| REF-05 | P0 | 查询结果不会随着主光标移动被替换 |
| REF-06 | P0 | 支持刷新、清除、取消结果展示及错误重试 |
| REF-07 | P0 | 按 URI 和完整范围去重，保留同一行不同位置的引用 |
| REF-08 | P0 | 显示实际查询结果，零结果与后端不支持分别处理 |
| REF-09 | P1 | 可过滤文件路径和结果文本，显示过滤数量与总数量 |
| REF-10 | P1 | 可选按所在函数二次分组；无法判断所属函数时保留在文件级 |
| REF-11 | P1 | 保留有限查询历史，允许返回上一个符号的引用结果 |
| REF-12 | P2 | 读写引用分类，仅在后端有可靠数据时提供 |

声明处理：公开引用执行命令与直接提供者接口的控制能力可能不同。“包含声明”开关仅在适配层确实能控制时提供；否则说明返回结果由后端决定，不通过文本猜测删除声明。

验收：不同作用域的同名局部变量不混在一起；点击引用显示准确现场；快速连续查询 A、B 时最终保留 B；源码变化后提示结果可能过期。

## 5. 公共交互与状态要求

### 5.1 命令与键盘

首版至少提供以下可从命令面板调用的命令：

- 打开代码阅读视图。
- 聚焦文件树、函数列表、Context、Relation、引用结果。
- 预览定义、预览类型定义、打开预览目标。
- 锁定或解锁 Context、锁定或解锁 Relation。
- 查询调用者、查询被调用者、设为关系根节点。
- Lookup References、刷新当前查询。
- 主阅读位置后退、前进。

默认快捷键在验证与 VS Code 和目标平台常用快捷键的冲突后确定。所有按钮和菜单动作均应可用键盘完成；图标提供提示文字。

### 5.2 持久化

- 持久化排序、过滤偏好、自动跟随开关和窗口配置。
- 可恢复锁定目标，但重新加载后必须验证文件和位置是否仍然存在。
- 不把整个源码或大规模引用结果写入工作区状态。
- 符号、关系缓存按文档版本失效；依赖文件变化后的语义缓存采用保守过期策略。

### 5.3 状态与错误

统一状态包括：未选择目标、加载中、有结果、无结果、不支持、失败、可能过期。

后端不可用时，文件树仍能工作；符号功能给出相关提示和重试动作，不反复弹窗。结果被截断时必须明确显示已展示数量，不能将部分结果显示成完整集合。

## 6. 技术实现建议

### 6.1 模块划分

| 模块 | 职责 |
| --- | --- |
| ReadingController | 管理主阅读位置、事件来源、联动与导航历史 |
| LanguageAdapter | 查询文档符号、定义、类型定义、调用层次和引用；统一返回结构 |
| FileTreeProvider | 文件树、过滤、文件监听和懒加载 |
| SymbolTreeProvider | 文件符号、排序、过滤和当前函数跟踪 |
| ContextController | 预览目标、锁定、历史、刷新与宿主控制 |
| RelationProvider | 关系根节点、方向、逐层展开和调用位置 |
| ReferencesProvider | 查询会话、分组、过滤、过期状态和历史 |
| RequestCoordinator | 防抖、结果版本检查、并发限制和失效处理 |
| Configuration | 工作区配置、偏好和状态持久化 |

建议使用 TypeScript 和 VS Code 标准扩展 API。树状导航优先使用 TreeView；只有确有布局需要的预览或图形界面才使用 Webview。

### 6.2 语言能力复用

优先验证以下公开命令或接口：

- `vscode.executeDocumentSymbolProvider`
- `vscode.executeDefinitionProvider`
- `vscode.executeTypeDefinitionProvider`
- `vscode.prepareCallHierarchy`
- `vscode.provideIncomingCalls`
- `vscode.provideOutgoingCalls`
- `vscode.executeReferenceProvider`

这些名称是待实现时核对参数、返回类型及最低 VS Code 版本的技术入口。不要根据扩展已安装就假定其所有能力可用；以实际请求结果和已验证能力为准。

公开命令不一定暴露取消令牌。逻辑取消必须通过请求序号和目标版本阻止旧结果落地；只有底层支持时才执行实际取消。语言服务尚未就绪与确实无结果可能难以完全区分，应允许重试，避免伪造精确诊断。

### 6.3 数据模型

- `SymbolTarget`：URI、名称位置、完整范围、符号种类、可用名称及签名。
- `PreviewTarget`：URI、范围、预览来源、定义或引用现场等模式。
- `RelationEdge`：调用者、被调用者、调用位置集合。
- `ReferenceSession`：查询目标、请求编号、引用位置集合、时间和过期状态。
- `ReadingState`：主阅读位置、主编辑器身份、Context 锁定目标、Relation 根节点及方向。

符号身份不可只使用名称；至少结合 URI 和位置，处理重载、同名静态函数和局部变量。符号位置随编辑变化后，应重新解析或标记过期。

### 6.4 请求与性能

- 初始防抖建议 200 ms，作为可调整默认值，经实测确定。
- 同一符号范围内移动光标时复用结果，避免重复刷新关系树。
- 对已发出的慢查询限制并发；新目标优先，旧目标结果丢弃。
- 源码片段按需读取，不为生成引用列表一次性读取所有文件。
- 目录和关系节点懒加载；大量引用应分批构建界面。
- 同时记录后端耗时与插件自身处理耗时，避免把后端解析时间算成界面性能。

初始验收目标：已有数据时，本地选择、锁定、过滤等交互的 P95 响应不超过 100 ms；不包含防抖和后端查询。性能基线和机器配置须记录，目标在技术验证阶段校准。

## 7. 开发阶段与交付物

以下为单人全职开发的初步估算，合计约 26–35 个工作日。范围以五项核心功能为主，不包含全部 P2；后端兼容问题可能调整估算。

| 阶段 | 预计时间 | 工作内容 | 交付与退出条件 |
| --- | --- | --- | --- |
| M0 技术验证 | 3–4 天 | 验证 C/C++ 后端五类查询、Context 两种宿主、布局和事件边界 | 可运行技术样例、后端能力表、选定首版后端及预览方案 |
| M1 阅读框架 | 4–5 天 | 扩展脚手架、统一状态、文件树、函数列表、基本导航 | 可安装开发版；文件切换、符号定位与过滤通过验收 |
| M2 Context | 4–5 天 | 自动定义预览、候选选择、锁定、调用现场预览、请求去重 | 主位置不被预览改变；乱序与锁定场景通过验收 |
| M3 Relation | 4–6 天 | Incoming/Outgoing、懒展开、根节点锁定、调用位置和循环处理 | 能围绕固定根节点完成上下游阅读 |
| M4 References | 3–4 天 | 引用会话、分组、片段、预览、跳转、刷新和过滤 | 完成从函数到引用现场再返回的阅读闭环 |
| M5 集成与发布准备 | 5–7 天 | 交互一致性、性能、错误状态、配置、文档和打包 | VSIX、测试记录、兼容性说明、已知限制和使用指南 |
| M6 可选增强 | 3–4 天 | 第二后端验证、更多 P1 能力或多根工作区 | 以实测结果更新支持矩阵；不计入核心估算 |

### 7.1 M0 必须回答的问题

1. 首版后端对 C/C++ 的符号、定义、类型定义、两个调用方向、引用分别提供什么结果？
2. 缺少编译配置、文件尚未索引、宏及重名符号时是什么表现？
3. Context 能否保持稳定位置、焦点和主编辑器身份？
4. 调用位置的 URI 和范围能否正确映射到源码现场？
5. 多定义、无结果、语言服务启动延迟如何呈现？
6. 哪些需求可以用通用 API 完成，哪些需要后端专用适配？

若调用层次能力不满足要求，先形成明确的适配或缩小支持范围方案，再进入 M3；不能用文本搜索结果冒充语义调用关系。

### 7.2 首个可用版本边界

M1–M4 完成后形成内部可用版本，必须包含：

- 文件树与当前文件函数列表。
- 常驻 Context，支持自动定义预览和锁定。
- 调用者、被调用者关系树，支持逐层展开和固定根节点。
- Lookup References，支持保留结果、预览和显式跳转。
- 主阅读位置与预览分离，五项功能联动无循环刷新。

可暂缓类型继承、复杂签名展示、多关系实例和读写分类。

## 8. 验证计划

### 8.1 固定样例工程

建立小型 C/C++ 工程，覆盖跨文件调用、同名静态函数、重载、局部变量遮蔽、类方法、多个调用位置、递归、宏、条件编译，以及函数指针和虚调用等已知受限场景。样例保留明确的预期结果及后端限制。

### 8.2 自动验证

- 对事件来源与锁定规则、乱序请求、过期状态和历史导航做单元验证。
- 对引用去重、关系循环、调用位置归属、符号范围匹配做单元验证。
- 通过 VS Code 扩展宿主验证五类查询到窗口数据的集成链路。
- 语言后端集成测试记录具体版本和工程配置；不把模拟后端通过当成真实语义兼容通过。

不为纯配置声明或简单透传逻辑堆积重复测试，重点验证会破坏阅读位置、结果正确性和状态一致性的逻辑。

### 8.3 人工阅读验收

| 场景 | 通过条件 |
| --- | --- |
| 文件树打开文件 → 函数列表定位 → Context 看定义 | 文件、符号、定义一致，焦点行为符合规则 |
| 固定 A → 展开调用者 → 选择调用现场 | 根节点不变，Context 显示正确调用位置 |
| 查询 B 的引用 → 浏览多个结果 → 打开一个结果 → 返回 | 结果集保留，主阅读位置可恢复 |
| 快速移动光标并切换文件 | 无过期结果覆盖，无递归刷新 |
| 修改未保存源码 | 预览使用当前内容；旧引用、关系按策略标记过期 |
| 后端缺失或查询失败 | 文件树仍可使用，各语义窗口状态明确且可重试 |
| 键盘操作与深浅主题 | 主要动作无需鼠标，目标高亮和状态可辨认 |

### 8.4 性能验证

分别选择小型工程和一个实际大型工程，记录文件数量、代码规模、机器配置、语言后端版本与冷启动/热查询结果。验证大目录、引用密集符号和深调用链，不预先承诺任意规模工程的固定查询耗时。

## 9. 风险与处理

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 不同语言后端能力不一致 | 调用关系缺失或结果差异 | 建立实测支持矩阵，首版固定验收后端 |
| Context 导致编辑器身份混乱 | 函数列表错切换、联动循环 | 集中管理主阅读位置，标注事件来源 |
| 编译配置不完整 | 定义和引用缺失 | 文档说明必要配置，提供重试和诊断入口 |
| 快速切换产生乱序请求 | 旧内容覆盖新目标 | 请求序号、目标检查和逻辑取消 |
| 编辑使位置失效 | 点击结果跳错行 | 文档版本跟踪、过期标记和刷新 |
| 大量引用与深调用树 | 界面阻塞、内存增加 | 懒加载、分批展示、缓存上限 |
| 函数指针和动态分派 | 静态关系不完整 | 保留后端语义，明确能力边界 |
| VS Code 布局能力限制 | 无法固定成完全相同界面 | M0 验证布局，支持用户移动视图 |

## 10. 发布完成标准

- 五项核心功能均可用，P0 需求完成并通过对应验收。
- 至少一个明确记录版本的 C/C++ 后端完成端到端验证。
- Context 和 Relation 的锁定、跟随行为与联动表一致。
- 不出现已知的预览抢焦点、旧结果覆盖、关系无限展开问题。
- 发布说明写明支持范围、工程配置要求、已知限制和性能测试环境。
- 提供 VSIX、安装说明、命令与配置清单、典型阅读流程。
- 发布至 Marketplace 属于独立后续动作，本计划的实现交付以可安装包和验证记录为准。

## 13. 完整文件符号（0.3）

用户要求函数列表具有 Source Insight 文件符号浏览体验：同时展示包含、宏、全局变量、结构体和函数。

- 默认全部符号，保留仅函数筛选；窗口名称改为“文件符号”。
- 复用语言服务的变量、类型、函数及成员层次，补充预处理包含和宏，支持 CRLF、多行、未保存内容和重复结果合并。
- 条目显示类别，保持源码排序、名称过滤、定位及既有联动。
- 源码扫描不计算条件编译，不递归解析头文件；语义准确性依赖工程配置。
- 通过 C 样例、单元测试、真实 clangd 和通用 VSIX 打包验证；Windows UI 继续按 Windows 指南验收。

## 14. 搜索式引用与阅读布局（0.4）

- 删除底部引用视图；Shift+F12 在正文编辑区打开可关闭的引用结果标签页。
- 顶部搜索框支持按路径/源码筛选，Ctrl+F 聚焦、Esc 清空、Enter 进入结果；结果按文件分组，保留分页、历史、刷新与过期提示。
- 点击结果定位源码，Alt+点击 Context 预览；结果页保留，关闭后可重新打开。
- 左侧仅文件符号，右侧辅助侧栏显示文件树，底部 Context 与 Relation。使用官方 secondarySidebar 注册，最低 VS Code 1.106。
- 不覆盖已保存的用户布局；旧安装通过手动移动视图完成迁移。
