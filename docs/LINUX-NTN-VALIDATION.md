# Linux 内核与 NTN 源码验证

基于已发布的 1.1.0 开展后续修复；当前修改暂未提交，原 1.1.0 标签不变。本文记录语法索引与选定语言服务场景，不将离线索引等同为完整的内核编译器语义。

## 验证范围

- 内核源码：`/home/guohao/am62x/workspace/linux/linux-7.0`，按默认排除规则有 63,043 个候选 C/C++ 文件。
- 同一内核构建：`/home/guohao/am62x/workspace/buildroot/output/build/linux-custom`，ARM64、GCC 15.2.0；可从 `.cmd` 文件提取 2,156 条编译命令。
- 后续整体源码：`/home/guohao/NTN/workspace/source`。按用户要求在内核验证完成后开始；每次使用当前根的独立数据库，不引入其他工作区的 SDK。
- 索引默认总预算 1,024 MiB、最高 25% CPU；实机为 96 个可用逻辑 CPU，按内存预算使用 2 个解析线程及 1 个协调线程。JS 堆、缓冲区和进程 RSS 分别记录，资源预算为协作式保护。

## 编译环境验证

原源码目录没有 `.config` 和 `compile_commands.json`。验证使用指定构建目录中的真实配置，并在临时目录生成数据库；普通源码和头文件映射到当前源码根，生成头文件使用构建目录。样本源码与构建副本的内容哈希一致。

本机 clangd 19 不接受 GCC 的 `-mabi=lp64` 及五个 GCC 专用选项；验证配置移除这些参数并加入 `--target=aarch64-linux-gnu`。四个真实编译单元（init/main.c、kernel/fork.c、kernel/sched/core.c、drivers/char/mem.c）检查通过。原始命令直接交给 clangd 会失败，插件本地索引不能消除编译参数错误。

真实 LSP 会话验证 rest_init、__schedule、copy_process 的目标均回到当前源码中的正确定义。调度源码有一条 unused-includes 提示，不计为编译错误。父工作区的 `.clangd` 存在针对 linux/buildroot 的 Background: Skip 规则；正常启用后台语义索引时需核对该配置，验证没有修改该文件。

NTN 初轮进程 RSS 峰值 1,266 MiB，补齐轮 1,120 MiB，完整缓存重开 690 MiB。1,024 MiB 是 JS 堆、可观测缓冲区及 RSS 增量的协作式预算，不能等同整个进程的操作系统硬限额；原生 WASM/SQLite 分配及垃圾回收时机仍可能带来短时越线。这是当前资源控制的边界，不能宣称总 RSS 始终小于 1 GiB。所有扫描只读源文件，未引入其他工作区 SDK，也未修改指定构建目录或工程配置。

内核全库独立宏审计已通过：63,043 个文件中检查 5,895,940 个宏定义与 1,432,611 处替换文本标识符，宏定义遗漏、出现位置遗漏、标识符乱序和文件处理失败均为 0。审计脚本修复了对 `$f0` 等 GNU/汇编寄存器名称的拆分误报，回归用例验证完整名称及位置。这项审计不覆盖宏展开后的编译语义或全部普通变量绑定。

纯预处理文件读取上限为 32 MiB，普通语法解析上限为 16 MiB；超限有明确诊断。大型文件的大纲最多列出前 5,000 个符号并提示上限，全部可识别符号仍进入持久库，支持全局查找与定义定位。未保存的大型编辑缓冲区采用更严格的内存保护，不把未保存文本写入磁盘索引。父子目录复用会验证当前文件内容；采用流式存储的超大文件在跨项目复用时重新分批提取，当前项目自己的缓存可直接复用。

## 缓存菜单使用

在工程文件、符号或 Context 面板的菜单中选择“管理本地缓存”，也可在命令面板运行同名命令。每项开头显示大小；选择一个或多个缓存，确认后删除。正在使用的项弹窗提示并保留；批量操作会跳过占用项，删除前还会再次检查占用。

缓存文件按数据库及其 WAL/SHM 辅助文件作为一组清理，旧 JSON 缓存可单独清理。管理范围为插件默认目录、当前配置目录及当前工作区的旧 JSON；不会递归删除未知文件。旧版本留下的 WAL/SHM、无法判断的占用标记会保守禁止删除。占用标记用于插件进程/线程之间的协调，并不控制其他程序任意直接修改数据库。
