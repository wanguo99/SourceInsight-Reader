## 已修复的问题

| 问题 | 修复与验证 |
| --- | --- |
| clangd 自动生成 YAML 尾部空文档触发配置错误，退出码却为 0 | 去掉多余分隔符，使用真实 clangd 检查完整输出中的配置错误和警告 |
| 移除自动配置改变原文件末尾换行 | 记录插入分隔换行，保留 CRLF、BOM 和无末尾换行状态，增加幂等与还原测试 |
| 配置标记损坏或重复时可能误改内容 | 只识别完整标记行，遇到不完整或重复标记拒绝写入 |

| 异步读取期间缓冲区或配置变化导致旧状态写入 | 写入前复查脏缓冲区、目录范围、开关、信任和磁盘内容 |
| 多根工作区中单个失败中断后续根处理 | 每个根单独捕获异常，继续处理其余目录；输出详细原因并提示失败 |
| 新增配置按钮缺少行为验证 | 验证按钮位于搜索框上方，调用目录管理命令且不跳转设置页面 |
| 打包检查缺少基础发行约束 | 检查根版本一致、Marketplace 图标大小与主题 JSON 可解析 |

## 验证与产物

- `npm run check`：语法、类型、命令注册、解析器资源校验和、版本、图标和主题检查。
- `npm test`：本地索引、Worker 缓存、目录范围、真实 clangd 定义与调用查询、自动配置及界面协议回归。
- `npm run package`：生成 VSIX，并单独验证 ZIP 完整性、版本、所需源码与私有/开发目录排除情况。
- `npm run test:host`：尝试启动真实 VS Code，Electron 被当前环境沙箱以 SIGTRAP 终止，未执行插件验收；不能视为通过。

## 正式发布前仍需桌面验收

在正常 Windows、Linux、macOS 环境安装新 VSIX，验证工程文件配置入口、多目录跨目录调用、屏蔽后结果清空、Context 预览、主编辑器前后退以及 clangd 重启后的范围变化。旧版本已有用户跨平台验证，但不能替代本次新功能验收。

只读目录、远程工作区、保存 .clangd 后自动同步等场景已有模拟回归；真实 Remote / WSL 文件系统权限和界面交互仍需实机验收。卸载插件不会自动撤销项目配置，卸载前应关闭自动配置以清除插件区块。

## 已知能力边界

- clangd 仍依赖正确的编译数据库、宏和工具链；无法只靠目录选择推导真实编译参数。
- `Index.Background: Skip` 限制后台编译单元索引，不屏蔽打开文件的解析、头文件依赖或清除历史缓存；更深层或用户级配置可覆盖规则。
- 配置更新不强制重启语言服务器；运行中的旧任务或旧结果必要时通过 clangd 重启清理。
- 本地索引主要面向 C，是语法与静态调用索引，不完整执行预处理，不保证函数指针、复杂宏及 C++ 语义精确。
- 当前 clangd 19 不提供 outgoing calls，相关语义测试跳过；本地 C calls 查询有独立测试。
- 文件同步通过写入前复查降低覆盖风险，不具备跨进程文件锁，无法承诺与其他写入程序原子互斥。
- 尚无大型 Linux 全量工程的统一内存、耗时基准，建议通过目录范围限制扫描量，不宣称任意规模工程均已验收。

结论：已修复发现的自动配置缺陷，生成可供安装验证的候选包。正式发布还需要完成上述桌面验收。此次检查不执行 Git 提交、推送、打标签或 Marketplace 发布。
