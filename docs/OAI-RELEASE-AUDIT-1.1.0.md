## XRAN_NUM_OF_SYMBOL_PER_SLOT 的具体原因

当前 OAI 目录只有 23 处使用，没有定义。它属于外部 xRAN API，官方 [xran_fh_o_du.h](https://github.com/o-ran-sc/o-du-phy/blob/master/fhi_lib/lib/api/xran_fh_o_du.h) 中存在该宏。OAI 的 radio/fhi_72/oran-init.c 首先包含此头文件，Findxran.cmake 要求外部 xran_LOCATION。检查当前 OAI 以及用户目录的已检索路径，没有找到相应 SDK 头文件；本工程也未找到编译数据库。

此外，oran-init.h 不直接 include xRAN，而依赖包含它的 C 文件先引入 SDK。旧本地索引缺少这种包含者上下文，即使当前项目中有 SDK 头文件，使用点仍可能无法定位。现在在普通可见范围查询无结果时，才执行有界包含者上下文回退，保留包含顺序和歧义；优先使用实时语言服务。

按用户二次审计要求，各项目完全独立：不再自动借用其他工作区根的 SDK。当前验证将这四份 OAI 文件复制到临时工程，SDK 位于同一工程的 sdk 子目录，23/23 使用点均定位成功；把 SDK 改为独立项目身份后，23/23 均拒绝跨项目解析，见 [本次隔离验证](validation/oai-xran-isolation-1.1.0.json)。未修改原 OAI，也未向用户工程安装测试 SDK。旧的 oai-xran-1.1.0.json 是撤回跨根支持前的历史记录，不代表当前行为。实际使用应在当前项目中提供匹配构建版本的 SDK，或为该项目的 clangd 配置正确编译命令。

## 父子目录双向复用（本轮新增）

支持先打开子目录再打开父目录，也支持先打开父目录再单独打开子目录。仅在同一缓存目录发现祖先/后代项目库，读取其本地语法事实。每个候选文件都重新读取当前源码、按配置解码并核对 SHA-256，内容一致才计入 inheritedFiles；变化的文件重新解析，删除或当前规则排除的文件不导入。无需手工操作数据库。

复用后写入当前项目自己的库，项目身份、符号可见性和调用图重新计算。不会继承其他项目的绑定、持久调用图、语言服务观察快照；父到子复用不会让子项目看到父目录范围外的 SDK。已有当前项目缓存优先，强制重建绕过继承。源库按只读方式打开，发现阶段有 2 秒预算；解析器不匹配、较新 schema、坏记录或锁冲突均回退正常解析。导入按文件进行，只保留 URI 目录和一个源连接，不将多份完整索引一起装入内存。

新增 test/index-inheritance.test.js 10 项回归与 REUSE-01～REUSE-08 人工用例。真实 OAI 源码只读测量见 [双向复用数据](validation/oai-index-inheritance-1.1.0.json)：

| 场景 | 文件数 | 复用父/子目录事实 | 新解析 | 实测总时间 |
| --- | --- | --- | --- | --- |
| openair1/PHY 无缓存 | 453 | 0 | 453 | 20.47 秒 |
| 从既有 OAI 父项目库打开 openair1/PHY | 453 | 453 | 0 | 9.54 秒 |
| 从 PHY 子目录库扩展为 openair1 | 539 | 453 | 86 | 13.85 秒 |

父到子样本比同一子目录冷建约减少 53% 时间，首批结果约 0.51 秒；这是本机一次对比，包含内容校验、目标数据库写入和重建调用图，不是所有项目的速度保证。仍需读取当前内容及写入新库，不能承诺零成本打开。最终 VSIX 宿主同时验证项目隔离、父到子和子到父导入后的实际查询行为。


## 受控多线程解析与资源限制（本轮新增）

索引协调线程继续负责缓存、数据库、作用域和调用图；文件解析交给有界 Worker 池。最高 CPU 预算固定限制为可用 CPU 的 25%，配置只能调低；协调线程也占一个额度，解析线程最多 4 个且受共享内存预算进一步限制。12 个可用核和默认 1024MiB 预算分为协调线程 512MiB + 两个解析线程各 256MiB。128～512MiB 预算、低核心或小于 32 文件的小工程不创建解析池。

并发数是第一层限制。每个线程按实际线程 CPU 时间节流，进程 CPU 时间的共享计数把 GC/WASM 辅助工作也纳入回压；预留调度余量。原生解析/GC 不能在任意指令处被 JavaScript 暂停，因此是合作式预算，不能表述为操作系统强制的瞬时硬上限；外部 clangd 等进程由其自身配置管理。初测仅按线程限速时，12 核配额下 1 秒峰值曾到 3.39 核；补充进程统计后，在 OAI openair1 539 文件样本中平均 1.90 核、1 秒峰值 2.50 核（约总 CPU 的 15.8%/20.9%），RSS 峰值约 760MiB，无失败或降级。该样本耗时 34.54 秒，不宣称线程增加能线性提速。

内存由所有本地语法索引线程共享，默认 1024MiB，还会受系统物理/可用内存的四分之一约束。按线程设置堆限额，使用共享统计控制 JS 堆+缓冲区合计，监测进程 RSS 增长与系统低内存状态；WASM、SQLite、GC 和其他 VS Code 部分无法由 V8 堆上限直接硬限制。解析组出现预算错误或退出时，先释放线程再串行重试；实测 OAI 完整 7309 文件初步扫描仍为 24951 函数、266578 调用，遇到一次资源保护后完成，无文件失败。最终实际安装包的连续重建和检查结果见 validation/parallel-release-1.1.0.json。

在途文件数受解析线程数限制；查询/编辑优先于等待解析的扫描，迟到事实不会覆盖编辑。流式加载缓存元数据，避免低预算时一次展开全部目录；扫描进度有心跳，低 CPU 等待上限随预算调整。主动休眠从 C/C++/预处理提取超时中扣除，避免限速造成误失败。缓存复用命中仍跳过解析，不把其他项目的调用图/语义观察导入当前项目。

新增 test/parallel-index.test.js 14 项，涵盖预算、合计内存、CPU 时间/辅助线程、旧运行时回退、提取时钟、前台优先、真实解析池、退出回收、串并行一致、迟到编辑和内存降级；人工验收新增 PAR-01～PAR-10，完整用例 217 项。真实资源样本见 [资源记录](validation/parallel-index-resources-1.1.0.json)。
