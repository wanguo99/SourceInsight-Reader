# 商用就绪审计与优化计划

审计基线：1.0.9 / `5338e36`，2026-10-24。开发期间保留 1.0.9；本计划不授权发布、推送或改动远程标签。用户已授权各阶段通过检查、测试和构建后创建本地 Git 提交。

## 目标与证据

目标是面向公开用户的稳定代码阅读工具：先确保 C/C++ 工程中的可信定位、即时预览、关系与引用浏览，再完善跨语言、长期阅读状态和高级关系。保留现有应用、领域、提供者、Worker 和 Webview 分层。

基线检查：Node 22.23.3 / Linux；`npm run check` 通过；单元测试 231 通过；clangd 19 集成测试 3 通过、1 跳过（outgoing 需 20+）；VSIX ZIP 校验通过。宿主测试本轮没有完成，不能作为通过证据。历史用户实机记录不等同持续跨平台自动化。

证据分类：复现＝补充样例或压力样例实际观察；代码＝静态路径确认；缺口＝当前未形成完整能力；验证＝尚缺相应环境证据。P0 阻断成熟商用承诺，P1 为稳定产品主线，P2 为后续竞争力。

## 分阶段交付与提交规则

| 阶段 | 交付 | 完成门槛 | 状态 |
| --- | --- | --- | --- |
| S1 准确性 | 修复误跳、语言/编码/工程范围、逐文件失败；标注回归 | 相关回归、check、unit、package 通过 | 完成，实机待验收 |
| S2 查询与结果 | 有界协调、语义策略、来源与配置身份 | 永久挂起/迟到/冲突/配置变化回归，完整构建 | 完成，诊断界面在 S4 |

| S4 用户体验与阅读能力 | 默认行为、引导、诊断、持久阅读、高级搜索和关系 | 自动回归与可执行手工用例，完整构建 | 完成，界面/跨语言待人工验收 |
| S5 质量与发布门槛 | CI、平台能力、契约、制品校验、基准和故障流程 | 本机可执行检查通过；外部环境明确待验收 | 完成，外部矩阵待执行 |
| S6 文档与验收交付 | 功能清单、全量测试用例、支持矩阵和最终安装包 | 用例覆盖已有和新增功能；逐项报告证据与限制 | 待开始 |

每阶段先补缺陷回归与验收步骤，实施后运行 `npm run check`、`npm run test:unit`、`npm run package`，再创建本地提交。改动涉及语义/宿主时运行相应集成；环境不支持时如实记录，不能以单元测试替代。阶段记录见 [OPTIMIZATION-LOG.md](OPTIMIZATION-LOG.md)。

“开发完成”与“商用验收通过”独立：Windows/macOS/Remote、真实 Java/Pylance、长期稳定性和 Beta 用户结果必须由相应实际环境产生；本轮应交付可执行流程，不填造通过记录。用户最后使用 [ACCEPTANCE-TESTS.md](ACCEPTANCE-TESTS.md) 进行功能验收。高级语义能力若受提供者限制，必须在支持矩阵中标明，不能以文字匹配冒充实现。

## 目标预算（尚非基线成绩）

- 标注语料已知误跳为零；确定跳转准确率目标 99%，未知单列。
- 热本地查询 P95 ≤100ms，语言服务就绪的常见预览 P95 ≤500ms；大工程首批结果目标 3 秒。
- 常规阅读无扩展自身超过 100ms 的同步长任务；截断必须可解释、可继续访问。
- 查询等待有预算；空、未就绪、不支持、错误、过期和不完整分别表示。
- 支持环境完成干净安装、升级及宿主验收；8 小时混合编辑无未处理异常和持续内存增长。
- 20～30 位不同项目 Beta 用户中，目标 90% 在五分钟内独立完成第一条阅读任务。

固定机器、项目、后端与冷/热状态后再测量预算。合成闭包/高亮样例仅证明路径，不外推为真实工程成绩。
