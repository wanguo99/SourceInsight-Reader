# 0.0.3 架构与维护说明

这次重构保留现有阅读功能，删除旧控制器接口和模拟 WebviewPanel 适配层。内部模块、索引缓存格式和 Webview 消息协议不保留旧版本兼容代码。

## 模块职责

| 层 | 入口 | 职责 |
| --- | --- | --- |
| 组装 | `src/extension.js` | 创建依赖、注册 VS Code 视图和统一释放资源 |
| 阅读应用 | `src/application/` | 阅读会话、主编辑器导航、自动跟随、命令注册和事件协调 |
| 领域数据 | `src/domain/` | 不依赖 VS Code 的 Symbol、SourceLocation、CallEdge、QueryResult 和查询状态转换 |
| 调用关系策略 | `src/relation-backend.js` | 后端选择、超时、请求合并、短期缓存、熔断与本地回退 |
| 提供者 | `src/providers/` | 将本地索引和语言服务结果转换为领域数据；私有保存语言服务原始句柄 |
| 功能会话 | `src/features/` | Relation 根节点与边查询、字符及引用检索会话、组合阅读面板 |
| 视图呈现 | `src/relation-pane.js` 等 | 将会话状态转换成视图数据，管理可跳转项目和用户操作 |
| 基础设施 | `src/infrastructure/` | 工作区文件目录、Webview 通道、Worker 调度及索引持久化 |
| 浏览器代码 | `media/`、`shared/protocol.js` | 渲染、交互、统一消息桥和双方共用的协议校验 |

`LanguageAdapter` 只负责符号、定义与引用查询；Relation 提供者和策略由组装入口单独创建。新增调用关系后端应实现 `contracts.d.ts` 中的 RelationProvider，再接入后端选择策略，不应向 UI 暴露原始 LSP 数据。

## 查询生命周期

Relation、字符检索和引用检索使用显式状态；请求代次阻止过期结果覆盖新查询。

- `idle → loading → ready / empty / failed`：首次查询。
- `ready → refreshing → ready / empty / retained`：刷新期间保留可用数据；错误不伪装成空结果。
- `stale`：源码或范围变化，保留显示但阻止使用过期位置跳转。
- Relation 根节点与 incoming / outgoing 分别维护状态；一侧完成即可显示，无需等待另一侧。
- 缓存按索引版本隔离；空结果缓存短于正常结果。手动刷新重置语言服务熔断，不触发全工作区索引重建。

Context 模型独立管理预览请求、快照、历史和只读源码；ReadingPanel 负责实际 Webview 生命周期与消息路由。预览中的旧快照不能继续跳转。

## 工作区及索引

`WorkspaceFileCatalog` 集中维护文件系统和文档事件、工作区根目录、扫描缓存及 glob 处理。各功能订阅同一目录服务，并应用自己的包含和排除策略；显式刷新绕过扫描缓存。

`indexEnabled` 独立控制本地 C 索引。选择 Relation 语言服务模式不会关闭符号和定义查询所需的本地索引。

索引线程使用单写入调度：前台查询优先、后台扫描分批让出执行权，每轮也给后台工作留出机会。后台扫描完成前仍可查询已有快照；期间收到的修改和删除以覆盖层合并，避免新修改被扫描结果覆盖。已有文件修改只重建受影响的调用边；新增、删除及路径变化使用完整图重建保证拓扑正确。

解析事实由 `JsonIndexRepository` 以版本化 JSON、文件内容散列和解析器标识持久化，批量原子写入。未保存缓冲区只覆盖内存，不作为磁盘事实写入缓存。缓存损坏或版本不符时重建。后续换用 SQLite 只需替换此持久化端口，不应改动解析器和视图。

Relation 底部索引提示通过独立状态通知更新：首次“索引创建中…”，后续“索引更新中…”，长扫描显示文件进度，完成显示统计，失败显示原因。提示不依赖是否已有当前函数，重新打开视图时发送最新状态。它不负责触发调用关系重查；索引内容变更事件负责使 Relation 查询失效并刷新。

## Webview 和检索

所有视图通过 `ViewChannel` 统一生成 CSP、资源地址和消息通道。消息包含协议版本、视图会话标识和递增序号；校验动作白名单和字段类型，拒绝旧视图、重复消息及不合法参数。浏览器端仅 `bridge.js` 获取原生 VS Code API。

Search Results 只生成一份 HTML，通过数据消息切换字符与引用模式，各模式保留独立的查询和分页。共同的会话基类负责选中项、每页 300 项、上/下结果导航及目标校验；引用分页覆盖全部引用，不受旧树形分组的每文件显示数量限制。旧 `ReferencesEditor` / `TextLookupEditor` 与对应重复脚本已删除。

## 验证及扩展边界

- `npm run check`：语法、命令注册、全源码 JS 类型检查，以及领域契约和状态转换的严格类型检查。
- `npm test`：纯领域状态、后端回退和熔断、Worker、缓存、增量/完整索引一致性、libbmc 样例、预览和导航、检索分页、协议与渲染回归。
- `npm run test:host`：真实 VS Code / clangd 集成；需要可启动 Electron 的桌面或 Xvfb 环境。当前受限环境中 Electron 在运行测试前被沙箱限制终止；未据此宣称桌面验收通过。
- Windows、Linux、macOS 使用相同 JavaScript 和 WASM 运行路径，均已由用户实机安装使用并确认可用；路径、盘符、UNC 和测试枚举另有自动回归。

本地索引仍是保守的 C 语法索引，不执行预处理、不精确求值条件编译，也不解析函数指针的运行时目标。完整的语言语义继续由语言服务提供。
