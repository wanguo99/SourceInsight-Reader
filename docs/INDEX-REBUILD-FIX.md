# 1.0.10 重建后误报内存预算修复

## 现场

用户的Remote输出先完成7256文件、24959函数、266605调用，随后重建变为0文件/7263未收录，再变为1文件/23函数/156调用、7262未收录。旧版文件收录能力和1024MiB预算在初次扫描可用，因此不能用持续提高上限代替修复。

原强制重建在同一Worker内清空索引和缓存Map，再立即读取heapUsed判定下一文件能否准入。清空引用不保证旧事实和JSON序列化临时对象已经被GC回收；瞬时堆占用可能使整轮扫描被拒绝。旧跳过分支还绕过了批次进度和让出执行。实际日志符合这条失效路径；GC时机不同，单次命令行实测也可能成功。

## 修改

- 强制重建等待旧Worker退出，再创建新Worker重新扫描；不依靠旧堆的GC时机，不提高默认上限、不取消软预算。
- 重建切换代次时清除旧覆盖、文档覆盖和首批快照；前台查询等待新结果。连续重建在退出等待阶段合并，关闭/禁用后旧异步任务不能启动新线程。
- 为新代次提前准备首批快照等待，旧线程退出期间发起的查询也能在首批结果到达时继续，不必等待整个工程重建结束。
- 被终止的缓存写入只清理该线程专属的临时文件，保留最后一次原子写入成功的缓存。
- 预算跳过仍按批次报告进度并让出执行；预算不足时继续明确标注不完整，不伪装完成。
- 内存诊断补充配置上限与V8实际堆限制，预算不足时输出结构化indexMemory记录，帮助区分真正不足与生命周期问题。

## 回归

新增3项自动回归：真实Worker受控模拟旧堆占用，原同线程操作得到0文件/全部未收录；改用公开重建入口后连续三轮恢复完整收录。覆盖退出等待、并发查询/重复重建、旧快照、关闭防复活及临时缓存清理。现有扫描超时测试改用不同Worker身份，继续检查重建后文件数变化和截止时间。

真实VS Code安装包另提供大工程入口，使用独立临时缓存，只读输入目录：

```sh
SOURCEINSIGHT_READER_INDEX_ROOT=/path/to/project \
SOURCEINSIGHT_READER_INDEX_FILES=/tmp/c-and-h-files.txt \
SOURCEINSIGHT_READER_INDEX_CACHE=/tmp/previous-facts.json \
npm run test:host -- --headless --index-rebuild --vsix=dist/wanguo-sourceinsight-reader-1.0.10.vsix
```

文件列表每行一个绝对路径，必须属于指定根；缓存参数可省略。验证初次扫描/缓存加载、写缓存、连续两次强制重建、不同线程身份、有效覆盖和代表性符号。它与普通的小样例宿主回归分开记录。

安装本次1.0.10修复包并重载后，运行“重建本地 C 调用索引”；可以保持默认1024MiB。C++、宏和大文件的既有能力边界仍见 [索引覆盖报告](INDEX-COVERAGE-FIX.md)。验收IDX-15/16已纳入完整用例。
