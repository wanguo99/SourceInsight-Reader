# 当前能力和环境矩阵

适用当前 1.1.7 功能。本文区分内置能力、外部语言服务和实际验证：实现路径存在不代表每种系统、工程或服务器版本都已人工验收。首次索引及日常操作见[使用说明](../README.md)。

## 按语言区分能力

| 能力 | 内置 C | C++ / clangd | Java | Python / Pylance |
| --- | --- | --- | --- | --- |
| 文件树、文件名 / 路径检索、屏蔽 | 支持 | 支持 | 支持 | 支持 |
| 当前文件 / 工程符号 | 含宏、类型、字段；受索引范围约束 | 离线语法大纲与宏，完整语义由提供者决定 | 由提供者 | 由提供者 |
| 定义 / 声明预览 | 根据可见性和唯一语法绑定定位；歧义时保留候选 | 由提供者和编译配置决定 | 由提供者 | 由提供者 |
| 类型定义 | 部分字段自身定位；完整类型跳转依赖服务 | 由提供者 | 由提供者 | 由提供者 |
| 调用关系与调用现场 | 直接C调用及类型绑定的成员调用；函数指针显示静态赋值候选，回调实现可反查注册成员和潜在调用者，支持匿名union直接回调别名；运行时及宏展开目标不推断 | clangd；语义 outgoing 需要 20+ | 由提供者 | 由提供者；动态目标可能未知 |

内置索引不执行完整宏展开、预处理条件求值、C++ 模板推导或编译器级类型分析。没有可靠绑定时返回未知或候选；相同文本的高亮不等于语义引用。不能用“扩展已安装”证明语言服务已就绪，也不能用空结果证明目标不存在。

## 索引方式与工程边界

| 范围 | 当前行为 |
| --- | --- |
| 显式启动 | 打开工作区、保存清单或发起查询不自动启动工程索引。通过管理工程文件保存模式和范围；Context 的开始 / 刷新索引直接使用已保存配置，不跳转管理页。启动后普通源码修改增量更新。 |
| 编译数据库 | 读取编译单元、支持的参数和可解析的工程内头文件依赖，不执行命令；最大 64 MiB，超限时需使用模块级数据库。 |
| 已导入文件 / 整个工程 | 只扫描受支持文件；屏蔽规则仍优先，移除条目不会删除源码。 |
| Buildroot / 独立输出目录 | 显式映射构建目录到当前工作区源码，按最长路径匹配；不改写数据库或 clangd 配置，不收录仅存在于外部构建目录的生成文件。 |
| 多根工作区 | 各根独立建立索引，结果受工作区与阅读范围约束；不自动借用其他工程的 SDK。 |
| 大工程与缓存 | 支持 CPU / 内存预算、持久缓存和同工程多窗口协调。预算或解析限制可能导致部分结果，必须查看实际状态和跳过原因。 |

## 运行环境

| 环境 | 能力及限制 |
| --- | --- |
| VS Code 桌面版 | manifest 最低版本为 1.106.0；Linux、Windows、macOS 使用相同 JS / WASM 实现。具体兼容性应按被测版本判断。 |
| Remote SSH / WSL / Dev Container | 插件在 workspace 扩展宿主运行；源文件、语言服务、数据库及缓存路径应在该宿主可访问。各远程组合需独立验收。 |
| 虚拟工作区 | 文件浏览、预览、搜索使用文件提供者；本地磁盘 C 索引不可用，语义功能依赖兼容语言扩展。 |
| 不信任工作区 | 只读阅读能力有限可用；禁止未获信任的 `.clangd` 托管写入。 |
| 浏览器 / vscode.dev | 没有 browser 入口，不在当前支持范围。 |
| 高对比、缩放、读屏与键盘导航 | 包含对应界面与交互支持；实际读屏器和系统组合需人工验证。 |

## 如何理解验证结果

自动检查、Node 测试、实际 VS Code 宿主测试和人工验收是不同层次。仓库配置了跨平台检查及最低 / 稳定版宿主 CI，配置存在本身不代表对应运行已经通过。

历史源码、工程和 VSIX 验证报告见[验证记录](validation/README.md)。应读取报告中的版本、环境、提交、包摘要、跳过项和剩余限制，不把旧版本结果转写成当前包的通过证明。人工验证可使用[完整验收用例](ACCEPTANCE-TESTS.md)逐项登记。

文档维护或本地自动检查不会隐式发布 Marketplace，也不能替代干净安装、升级回滚、真实语言服务、远端连接和长期运行验收。问题收集方式见[反馈说明](../SUPPORT.md)。


工程范围同时限制本地索引和插件的语言服务结果。宿主机系统头文件、未导入的SDK以及其他工程的同名定义不会自动作为结果或缓存内容返回；依赖源码需纳入当前工程范围。过滤不控制clangd内部的编译依赖读取或其他扩展提供的原生跳转。


Relation对包含链不完整且当前工程宏定义唯一的未绑定出现位置，可列出有明确提示的候选使用；这不改变普通定义跳转或References的确认绑定要求。同名宏歧义、其他声明绑定、undef及工程范围规则仍生效。

C 标识符着色使用当前源码角色与工程内唯一确认绑定；函数指针成员调用按函数分类，成员值读取保持成员分类，EXPORT_SYMBOL 参数不继承声明样式。主编辑器与 Context 共用合并规则，本地标识符分类优先于冲突语义 token；未绑定及仅有 Relation 候选的标识符使用默认前景色。颜色查询有预算与按文档版本 / 索引修订失效的缓存，不启动全工程扫描；索引变化会重新着色。此校正限定 Source Insight 主题、启用语义着色的 C / C 兼容头文件。
