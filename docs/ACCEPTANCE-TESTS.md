# 完整功能测试与用户验收用例

适用版本：1.0.9 开发优化版。状态：用例持续更新；本文的“预期”不是已经人工通过。自动化证据见 [OPTIMIZATION-LOG.md](OPTIMIZATION-LOG.md)，能力边界见 [COMMERCIAL-READINESS.md](COMMERCIAL-READINESS.md)。

## 执行方法与结果记录

1. 保存个人设置，用干净 VS Code Profile 安装最终 `dist/` VSIX；记录插件提交、VS Code/OS、语言扩展/服务器版本、项目和编译配置。
2. 首先执行 FIRST、FILE、SYM、CTX、REL、REF、SEARCH、NAV、SCOPE、SET 组；再执行新功能和环境相关组。
3. C 基础用例关闭语言扩展，验证本地能力；语义用例启用 clangd 20+ 并等项目就绪。Java 使用 Red Hat Java 标准模式，Python 使用 Python/Pylance 并选解释器。
4. 每条结果填 PASS/FAIL/BLOCKED/N/A，附实际结果、截图/日志；缺环境写 BLOCKED。不支持的后端能力写 N/A 并检查提示，不计成功实现。
5. 测试源码修改前备份；用独立样例工程完成屏蔽、配置和故障用例。

记录格式：`用例 ID | 日期 | 环境/提交 | 实际步骤及结果 | PASS/FAIL/BLOCKED/N/A | 证据/问题链接`。复现失败记录最小源码、查询位置、期望位置和后端；诊断包默认不含源码和绝对路径。

## 样例约定

基础 C/C++ 使用 `examples/cpp`：`leaf` 为被调函数，`process_request` 包含两处调用；测试前核对实际名称。Java/Python 使用 `examples/java`、`examples/python` 的 `leaf` / `process`。复杂 C 用例使用 `source-example/libbmc`，配置按 `docs/LIBBMC_CLANGD.md`。故障和多根用例使用临时副本。

NAV 回归小工程创建 `api.h`、`a.c`、`b.c`：

```c
/* api.h */
struct Record { int value; };
enum Mode { ACTIVE = 1 };
int leaf(void);
/* a.c */
#include "api.h"
int leaf(void) { return ACTIVE; }
/* b.c */
#include "api.h"
int arg;
int prototype(int arg);
static int other(void) { return 2; }
static int (*leaf_callback)(void) = other;
int run(struct Record *r) { int arg = leaf(); return arg + r->value + leaf_callback(); }
```
