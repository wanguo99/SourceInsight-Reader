# 1.0.10 索引漏收录与解析恢复修复

## 用户现场与根因

用户反馈：7251个文件、20677个函数、266795处调用，12个文件/缓存失败，3579个文件含语法错误，部分内容无法导航。对实际openairinterface5g目录只读核查，12项包括10个被判为C++的头文件、1个注释编码异常文件、1个略大于8MiB的SQLite源码。源码和工程配置没有改写。

实质缺陷包括：

1. `defs_nr_UE.h`、`phy_scope_interface.h`、`task_ans.h` 的C++兼容分支使用 `std::atomic`，原检测器因此拒绝整个文件，导致C声明和依赖的字段/类型漏收录。
2. GCC后置 `__attribute__((aligned(...)))`、函数参数或初始化列表内的条件指令不被当前C grammar完整接受；数组声明及关联引用会受恢复节点影响。
3. `ch_desc_proto.c` 的异常UTF-8字节仅出现在注释中，原实现仍拒绝整个文件。
4. SQLite源码约8.07MiB，刚好超过旧8MiB限制；直接增加完整遍历预算会增加资源压力，因此采用有明确限制的顶层符号模式。
5. 状态文本混合“后端不支持”“预算跳过”“解析恢复”和真正失败；解析器ERROR不等同编译器诊断，也不表示整文件完全未收录。原有效覆盖集合还包含扫描失败的文件。

## 处理方式

- 使用保留UTF-16长度与CRLF位置的内存语法投影：只裁去C模式下已确定的 `__cplusplus` 专属内容；其他构建标志保持未知。去除GCC属性元数据，在参数/调用/初始化上下文保留条件分支内容并屏蔽不被grammar接受的条件指令。源码文件不变，这不是完整预处理器。
- 仅当非法UTF-8字节全部位于注释中时，使用与UTF-8编辑器一致的替换字符继续解析并记录提示；不猜测文件编码，不修复非法标识符/字符串，NUL和其他解码错误仍拒绝。
- 8MiB内保持完整语法事实提取；8～16MiB收录顶层函数、声明、类型等，明确标注未索引函数体/局部变量/调用；超过16MiB硬上限仍跳过。原有解析时间、事实数量和内存软预算继续有效。
- 缓存事实升级facts-9，旧缓存自动失效。失败文件退出有效覆盖；真正C++头文件交语言服务，不能伪造C绑定。
- 新增命令 **SourceInsight-Reader: 查看本地索引问题**：区分失败、C++后端需求、预算、解析恢复、编码提示和仅顶层模式，提供文件、可用位置及已收录符号数。上限5000项，选择后重新检查工程范围。
- 脱敏诊断仍不导出路径或源码；新增解析恢复、C++后端需求、资源跳过、编码提示、仅顶层模式的聚合计数。保留旧syntaxErrors字段作为兼容别名，其含义为解析恢复文件数。
