# Release versions

The user requires a new version for each subsequent requested change. Version iteration restarted at 0.0.1. Increment the patch version for each later requested change and rebuild the VSIX. Patch numbers range from 0 to 99: 0.0.1 → 0.0.2 → … → 0.0.99 → 0.1.0 → 0.1.1; likewise 0.1.99 → 0.2.0. Do not continue the previous 0.10.x or 1.0.0 sequence, or repeatedly overwrite a released version. Keep package.json, the root package-lock.json version fields, installation instructions, and the latest changelog entry consistent. Do not change third-party dependency versions when updating the extension version.
