# SourceInsight-Reader


在 Source Insight 主题下，主编辑器与 Context 共用 C 标识符分类：已确认绑定按索引类型着色，函数指针成员调用按函数显示，EXPORT_SYMBOL 参数按引用显示。未绑定或仅有 Relation 候选的标识符使用默认前景色（本主题为黑色）。C 兼容头文件即使被识别为 C++ 也支持此校正；真正的 C++ 头文件仍交给语言服务。索引更新后会自动刷新颜色。
[English](README.en.md) · [配置参考](docs/CONFIGURATION.md) · [命令参考](docs/COMMAND-REFERENCE.md) · [问题反馈](SUPPORT.md)

Source Insight 风格的 VS Code 代码阅读插件。通过工程文件、符号列表、定义预览和调用关系，在当前位置理解代码、追踪调用，并保存阅读进度。适合阅读 C 工程、嵌入式代码和内核源码，也可配合语言扩展阅读 C++、Java 和 Python。

**当前版本：1.1.7。需要 VS Code 1.106.0 或以上版本。** C 基础阅读可使用内置离线索引，无需先编译工程或安装 clangd；完整语义分析由对应语言扩展提供。

## 功能概览

| 功能 | 使用方式 |
| --- | --- |
| 工程文件 | 浏览目录树，按文件名或路径查找文件；导入所需目录或文件，屏蔽无关内容。 |
| 文件与工程符号 | 查看函数、变量、宏、枚举、类型和成员；筛选当前文件符号，查找工程符号。 |
| Context 定义预览 | 查看定义、声明和包含函数，保留主编辑器位置；支持锁定、预览历史、查找、完整函数及旁侧打开。 |
| Relation 调用关系 | 在横向调用图或大纲中查看“谁调用它 / 它调用谁”，选择具体调用现场并跳转源码。 |
| 引用与全文检索 | Lookup References 查询符号引用；Lookup Text 查询普通文本、正则或多行内容，支持结果筛选、分页、历史和保存检索。 |
| 阅读记录 | 保存书签、笔记和阅读任务，重新打开工作区后继续阅读。 |
| 本地索引与缓存 | 按选定范围建立索引，支持增量更新、持久缓存、父子目录缓存复用及受 CPU / 内存预算约束的并行解析。 |
| 阅读外观 | 提供 Source Insight 主题、C 语法补色、字体与颜色设置，以及可选的键位和布局预设。 |

## 安装

准备发布包 `wanguo-sourceinsight-reader-1.1.7.vsix`，在 VS Code 扩展视图右上角选择 **… → 从 VSIX 安装…**，安装后按提示重载窗口。

也可以在发布包所在目录执行：

```sh
code --install-extension ./wanguo-sourceinsight-reader-1.1.7.vsix
```

若已安装同版本，需要覆盖验证新的重新打包文件，可在命令末尾加 `--force`，安装后重载窗口；同版本包请按随包SHA-256校验文件区分。

在 Remote SSH、WSL 或 Dev Container 窗口中，请确认插件安装在打开源码的扩展宿主一侧；源码、编译数据库、语言服务和自定义缓存路径也应在该环境中可访问。插件没有面向 `vscode.dev` 的浏览器入口。各环境的能力与验收边界见[支持矩阵](docs/SUPPORT-MATRIX.md)。

## 第一次使用

1. 在 VS Code 中打开源码文件夹或工作区。
2. 打开命令面板，运行 **SourceInsight-Reader: 打开阅读工作台**。
3. 首次使用时，从工程文件视图右键菜单或命令面板打开 **管理工程文件**，选择索引方式与范围并保存配置。
4. 点击 Context 面板的 **开始索引**，直接使用已保存配置创建索引；索引建立后同一个按钮显示 **刷新索引**，再次点击重新扫描，不跳转配置页。管理页底部也可保存并开始索引。
5. 查看面板中的索引进度；打开源码，将光标移到函数或符号上，通过 Context 预览定义、通过 Relation 浏览调用关系。

“刷新索引”沿用已保存的模式、导入范围、编译数据库和路径映射，重新读取编译清单并复用仍有效的缓存；不采用管理页未保存的草稿。索引处理中按钮显示“索引处理中…”并禁用，失败后可重试。需要改范围时使用“管理工程文件”。

**打开文件夹不会自动启动工程索引。** 切换文件、发起定义查询或点击“保存配置”也不会替代“开始索引”。索引范围会保存到工作区；重新打开工作区或修改模式、范围后，需要再次显式开始。启动后，普通源码编辑和保存按增量方式更新，已有有效缓存会复用。

### 选择索引方式

| 模式 | 适用情况 | 操作 |
| --- | --- | --- |
| `compile_commands.json` | 已有编译数据库，希望按实际编译单元缩小范围 | 选择数据库；索引列出的源文件及可解析的工程内头文件依赖。 |
| 已导入文件 | 只读某个模块，或暂时没有编译数据库 | 左侧勾选目录 / 文件；右侧取消勾选移除条目。支持 Shift 连选和批量取消。 |
| 整个工程 | 工程较小，或确实需要扫描整个工作区 | 选择整个工程；仍遵循支持的文件类型和屏蔽规则。 |

仍可按需添加任意目录或单独文件。选中目录后，其子目录和文件都能单独取消或恢复，父目录显示部分选中状态；右侧同时列出已选条目和排除项，勾选排除项可恢复。排除整个子目录后，也可只重新勾选其中需要的文件。保存后这些选择会保留，其他已选内容不受影响；不会删除源码，已有独立屏蔽规则仍然优先。导入管理、屏蔽管理也可从工程文件视图的右键菜单进入。

本地索引及插件的定义、类型、声明、引用、工程符号、Relation 和语义缓存结果统一遵守已保存的工程范围。语言服务返回的 `/usr/include`、宿主机 SDK 或其他未导入路径也会被过滤；SDK 源文件需位于当前工程并显式纳入范围，不能自动借用另一工作区的同名头文件。clangd 仍按编译配置解析依赖，本插件的范围过滤不改写其他扩展的原生跳转行为。

### 编译数据库与路径映射

数据库模式只读取编译记录，**不会执行其中的编译命令**，也不会因为解析失败自动退回全工程扫描。支持 `arguments` / `command`、相对 `directory/file`、`-I` / `-iquote` / `-isystem` / `-idirafter`、强制包含和可解析的字面 include。数据库超过 64 MiB 时，应提供模块级数据库。

Buildroot 或内核独立构建目录与当前源码路径不同时，在管理页点击 **添加构建目录 → 源码目录映射**，依次选择编译记录中的构建目录和当前工作区中的源码目录，再开始索引。例如：

```text
构建记录：/work/buildroot/output/build/linux-custom
当前源码：/work/linux/linux-7.0
```

支持多个映射，嵌套目录按最长路径优先匹配。插件先按记录的 `directory` 解析路径，再映射源文件、头文件搜索路径和强制包含路径；读取当前源码，不改写原始数据库或 clangd 配置。普通 `make O=...` 的记录若已指向原始源码，则无需映射。

仅存在于工作区外构建目录中的生成文件会显示为缺失，不会被偷偷纳入索引。宏展开 include、响应文件、编译器内建搜索路径和完整条件编译仍需语言服务处理；汇编不在本地 C 索引范围内。

## 日常阅读

- **找文件 / 符号**：使用工程文件搜索框，或运行“查找工程文件”“查找全局符号”；文件符号列表支持筛选和排序。
- **读定义**：在 Context 中预览目标；需要固定某段源码时锁定 Context，需要同时对照时使用“固定预览到旁侧编辑器”。
- **追调用**：将函数设为 Relation 根节点，选择调用方向和具体调用位置；Context 与 Relation 可以分别锁定。
- **查引用或文本**：引用查询与纯文本检索是不同操作。结果在 Search Results 中查看；源码或范围改变后，如显示过期状态，请刷新后再跳转。
- **保存进度**：用“添加书签和笔记”“保存阅读任务”“保存当前检索”记录阅读位置，再从相应管理命令恢复。

索引期间或资源受限时可能只有部分结果。请结合结果来源、索引状态和“查看本地索引问题”判断覆盖情况，不能把空结果直接当作不存在定义、调用或引用。

## 语言支持

| 语言 | 内置能力及配套配置 |
| --- | --- |
| C | 可直接使用离线索引。需要准确反映编译选项、宏展开和条件编译时，配置 clangd 与 `compile_commands.json`。 |
| C++ | 提供离线语法大纲与宏导航；完整定义、引用和调用关系依赖 clangd 与工程编译配置，语义 outgoing 调用需要 clangd 20+。 |
| Java | 使用 Red Hat Java 扩展提供语义能力，需以标准模式正确加载工程。 |
| Python | 使用 Python / Pylance 扩展并选择工程解释器；动态调用的完整性取决于语言服务。 |

`navigationBackend` 和 `relationBackend` 默认均为 `auto`：普通查询优先使用可用语言服务，再尝试受支持的本地 C 回退；非函数符号的使用关系、结构体成员引用及回调实现的上游优先使用本地类型绑定结果，补充函数指针的静态赋值候选。可分别选 `local` 或 `languageService` 排查来源；选择 Relation 语言服务模式不会自动关闭本地索引。

内置索引不执行完整预处理，不精确求值条件编译，也不推断函数指针的运行时目标。工程符号按工作区根隔离，不借用其他工程的 SDK；详细边界见[支持矩阵](docs/SUPPORT-MATRIX.md)。

### 结构体成员与函数指针

将光标放在 `adap->algo->master_xfer(...)` 的成员名上查看 Relation：左侧显示已索引范围内对同一成员槽的调用位置，右侧显示初始化或赋值中的函数实现候选。候选的位置可查看赋值行，双击函数节点可打开函数定义；不同结构体的同名成员不会混在一起。

支持直接函数指针成员、typedef 回调、函数指针数组及同一匿名 union 中的直接函数指针别名。例如内核的 `master_xfer` 和 `xfer` 共用成员槽，`.xfer = omap_i2c_xfer_irq` 会作为实现候选列出。普通成员可查看使用它的函数，并通过引用查询定位读取、写入和初始化。直接以回调实现函数为根，也能反查注册成员及该成员的潜在调用者；语言服务返回空调用列表时会检查本地索引。

范围需包含相关声明头文件、调用方和驱动实现。以 `i2cdev_read` 为例，除了 `drivers/i2c/i2c-dev.c`、`include/linux/fs.h` 和 `include/linux/i2c.h`，还需导入 `fs/read_write.c` 才能看到 `vfs_read` 等潜在上游；修改导入范围后点击 Refresh Index。候选表示静态赋值关系；宏生成目标、指针拷贝、对象运行时绑定和条件分支仍需结合语言服务或人工检查。开始 / 刷新索引时会重建旧格式的本地缓存。

### 宏、结构体变量和枚举的使用位置

将光标放在宏定义或使用处、局部 / 全局变量、结构体 / 枚举类型、枚举项及 typedef 上，Relation 左侧显示“使用位置”。函数内引用按包含函数分组；初始化、其他宏和文件作用域的使用保留实际位置。按声明绑定并过滤同名遮蔽，不把自身定义算作使用；非函数符号不生成函数调用下游。函数式宏同样支持，但不展开宏体推断运行时调用。

内核工程缺少生成的 `asm/...` 头文件时，包含链可能不完整。若当前工程中该宏只有一个定义，Relation 会把尚未绑定的同名使用列为“候选使用位置”，并提示包含链缺失；点击定义或使用处均可查看。已绑定到其他声明、字段或局部变量、存在多个同名宏、明确 undef 之后及完全没有依赖线索的位置不会据此猜测。普通定义跳转和 References 仍要求确认绑定。

横向关系图把行号放在名称后面，如 `reader_usage :42,57 +2`。点击行号预览对应使用处，点击 `+N` 选择更多位置；双击名称打开定义。名称过长时省略，完整名称、路径和候选说明可悬停查看。所有节点保持一行高度，跟随字体大小调整。

这些本地使用关系支持 C 和 C 头文件；C++ 仅宏支持本地绑定，其他 C++ 符号依赖语言服务。请先导入定义和使用方，再开始或刷新索引。条件分支不求值；达到查询预算会明确提示结果不完整。

## 快捷键与布局

默认保留现有布局，Source Insight 导航键位默认关闭。可运行 **选择键位预设** 或 **应用 Source Insight 布局** 主动调整。颜色主题通过 VS Code 的“首选项：颜色主题”选择 **SourceInsight-Reader Source Insight**，插件不会自动切换主题。

| 按键 | 动作 | 生效条件 |
| --- | --- | --- |
| F8 | 固定 / 取消同名文本高亮 | 主编辑器和 Context；主编辑器中会覆盖 VS Code“下一个问题” |
| Ctrl+Alt+H / macOS Cmd+Alt+H | 同名文本高亮 | 主编辑器中的备用键位 |
| F2 | 同名文本高亮 | 仅启用 `symbolHighlightUseF2` 后；默认仍可用于重命名 |
| Alt+= | 跳转定义 | 启用 `sourceInsightKeys`，且焦点位于编辑器 |
| Alt+, / Alt+. | 阅读位置后退 / 前进 | 启用 `sourceInsightKeys` |
| Shift+F12 | Lookup References | 启用 `sourceInsightKeys`，且焦点位于编辑器 |
| Alt+Shift+S / Alt+Shift+P | 查找工程符号 / 文件 | 启用 `sourceInsightKeys`，且焦点位于编辑器 |
| Alt+F8 / Alt+Shift+F8 | 下一项 / 上一项查询结果 | 启用 `sourceInsightKeys`，编辑器中已有引用或文本结果 |

启用 `sourceInsightKeys` 后，Search Results 列表内使用 F8 / Shift+F8 浏览结果。同名文本高亮不表示这些位置属于同一语义符号。键位冲突可在 VS Code“键盘快捷方式”中按命令 ID 单独调整，全部命令见[命令参考](docs/COMMAND-REFERENCE.md)。

## 大工程、资源预算与缓存

先选择需要的模块，再观察索引覆盖和资源使用。**屏蔽规则优先于导入范围**：显式导入的文件若仍被排除，不会因此强制收录。工程文件列表、本地索引和全文检索各有自己的 glob 设置，调整文件列表显示不等于改变所有查询范围。

在插件 **设置 → 索引与屏蔽** 中调整资源预算：

- CPU：5–100%，默认 25%。
- 内存：固定上限默认 1024 MiB，也可按启动时可用内存的 5–90% 计算预算。
- 设置页支持滑块、数字输入和资源预览。预算不会预先占满，也不是操作系统硬配额；其他语言扩展有自己的资源占用。

以下是资源设置示例，键名与默认值以[配置参考](docs/CONFIGURATION.md)为准：

```json
{
  "sourceInsightReader.indexCpuLimitPercent": 25,
  "sourceInsightReader.indexMemoryMode": "fixed",
  "sourceInsightReader.indexMemoryLimitMb": 1024
}
```

缓存根目录默认使用扩展全局存储，也可设置 `sourceInsightReader.cacheDirectory`，支持绝对路径、`~` 和 `${userHome}`。根目录按工程名及路径摘要区分项目，每个项目包含 `indexes` 和 `logs`；远程窗口使用远程扩展宿主的目录。

设置页会显示实际路径。切换缓存目录不会搬移或删除旧文件；使用 **管理本地缓存** 查看大小、选择并删除闲置缓存，使用中的缓存会被保护。同工程多窗口协调索引写入并复用已提交数据，未保存文本留在各自窗口中。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 打开工程后没有索引 | 是否点击了“开始索引”；“保存配置”只保存范围；`indexEnabled` 是否启用。 |
| 只找到少量文件 | 当前模式、已选目录、屏蔽规则、编译数据库中的路径和映射；查看索引问题及日志中的跳过原因。 |
| 定义、引用或调用不完整 | 结果来源、语言服务是否就绪、是否有未保存修改，以及本地 C 的语法边界；C++ 语义 outgoing 检查 clangd 版本。 |
| 修改路径映射后没有变化 | 重新点击管理页的“开始索引”；映射不会自动修改 clangd 配置。 |
| 内存不足或索引中止 | 缩小范围或调整预算，再从“开始 / 更新索引（选择模式）”重新开始；真正 OOM 后不会无限自动重启。 |
| 远程窗口读不到文件或缓存 | 确认插件安装位置、远程文件权限和实际缓存路径，不要使用另一台机器上的本地路径。 |
| 主题或键位与预期不同 | 检查当前颜色主题、显式用户 / 工作区设置及键位预设；F8 高亮与结果列表的 F8 导航作用不同。 |

运行 **能力与工程诊断** 查看后端与工程状态；需要反馈时运行 **导出脱敏诊断**，并按照[反馈说明](SUPPORT.md)提供最小复现。插件自身不上传源码或发送遥测；阅读记录、缓存和日志可能包含私有信息，详见[隐私说明](PRIVACY.md)。
