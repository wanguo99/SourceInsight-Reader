# SourceInsight-Reader

[English](README.en.md)

Source Insight 风格的 VS Code 代码阅读插件。通过工程文件、符号列表、定义预览和调用关系面板，在当前位置理解代码、追踪调用并保存阅读进度。

## 功能介绍

| 功能 | 说明 |
| --- | --- |
| 工程浏览 | 独立页面通过左右分区复选框选择目录或文件，支持 Shift 连选，保存工程清单；按文件名或路径查找，屏蔽不需要的内容。 |
| 符号导航 | 查看当前文件的函数、变量、宏、枚举和类型，跟随当前函数，搜索工程符号。 |
| 定义预览 | 在 Context 面板查看定义和声明，保留主编辑器位置；支持锁定、历史记录、预览内查找和旁侧打开。 |
| 调用关系 | 在 Relation 图或大纲中浏览调用者、被调用者，查看并跳转到具体调用位置。 |
| 引用与搜索 | 查找符号引用并查看源码片段；支持全文、正则和多行搜索，保存查询记录。 |
| 阅读记录 | 保存书签、笔记和阅读任务，重新打开工程后继续阅读。 |
| 本地索引 | 内置离线 C 索引与 C++ 语法大纲；索引持久化、增量更新，可复用父子目录缓存，支持受 CPU 和内存预算约束的并行解析。缓存管理菜单显示大小，支持单项和批量清理，保护使用中的缓存。 |
| 阅读外观 | 提供 Source Insight 主题、C 语法补色，以及字体、颜色、背景和可选快捷键预设。 |

C 基础阅读无需编译或安装语言服务。本地索引不执行完整的宏展开和条件编译求值；完整语义分析由对应语言扩展提供。每个工作区文件夹独立索引。

## 安装与使用

需要 **VS Code 1.106.0 或以上版本**。

1. 准备发布包 `wanguo-sourceinsight-reader-1.1.3.vsix`。
2. 在 VS Code 中打开扩展视图，点击右上角 **… → 从 VSIX 安装…**，选择该文件。
3. 打开源码文件夹，在命令面板运行 **SourceInsight-Reader: 打开阅读工作台**。
4. 点击 Context 面板或命令面板的 **开始索引（选择模式）**，选择一种方式：
   - **compile_commands.json**：选择编译数据库，根据列出的源文件和可解析的工程内头文件依赖建立索引。
   - **已导入文件**：在左侧目录树勾选目录或文件，右侧取消勾选可移除；先点击一项，再按住 Shift 点击另一项即可批量操作。
   - **整个工程**：索引已打开工作区内的支持文件，仍遵循屏蔽规则。
5. 点击管理页的 **开始索引**，完成后通过 Context 和 Relation 阅读代码。

**每次打开文件夹默认不启动工程索引**，切换文件、定义查询和保存清单也不会启动。选择范围会保存到工作区；重新打开、修改模式或清单后，需要再次点击开始索引。开始后普通源码修改仍增量更新，已有缓存会复用。移除条目不会删除源码。

编译数据库支持 `arguments` / `command`、相对 `directory/file`、`-I` / `-iquote` / `-isystem` / `-idirafter`、强制包含及可解析的字面 include。只读取数据库，不执行编译命令，不等同完整预处理；宏展开 include、响应文件和编译器内建搜索路径仍需语言服务。数据库路径可以位于构建目录，但源文件必须指向当前工作区；不借用其他工作区的 SDK。超过 64 MiB 的数据库需生成模块级清单。缺失依赖及跳过项记录到日志。

也可以使用命令行安装：

```sh
code --install-extension ./wanguo-sourceinsight-reader-1.1.3.vsix
```

按工程语言配置语义能力：

| 语言 | 配置说明 |
| --- | --- |
| C | 可直接使用内置索引；需要准确反映编译选项和条件编译时，配置 clangd 与 `compile_commands.json`。 |
| C++ | 内置符号大纲和宏导航；完整定义、引用及调用关系需配置 clangd 与 `compile_commands.json`，语义 outgoing 调用需 clangd 20+。 |
| Java | 安装 Red Hat Java 扩展，使用标准模式并正确加载工程。 |
| Python | 安装 Python 和 Pylance 扩展，选择工程解释器。 |

首次使用可运行 **SourceInsight-Reader: 入门指南**；结果缺失时运行 **能力与工程诊断**。外观和功能选项通过 **SourceInsight-Reader: 设置** 调整。

[配置说明](docs/CONFIGURATION.md) · [功能与环境支持](docs/SUPPORT-MATRIX.md) · [测试用例](docs/ACCEPTANCE-TESTS.md) · [问题反馈](SUPPORT.md)

固定 / 取消同名符号高亮：主编辑器及 Context 使用 **F8**，也可使用 **Ctrl+Alt+H**（macOS：Cmd+Alt+H）。F2 默认保留重命名，可在插件设置中启用 F2 高亮。F8 在主编辑器内覆盖 VS Code 的“下一个问题”；可通过“键盘快捷方式”自行调整。启用 Source Insight 快捷键后，主编辑器使用 **Alt+F8 / Alt+Shift+F8** 浏览查询结果；结果列表内仍使用 F8 / Shift+F8。

索引资源可在插件设置的“索引与屏蔽”中调整：CPU 支持 5–100%；内存可选固定上限或当前可用内存的 5–90%。滑块与数字输入同步，保存前可预览预计线程数和内存预算。默认仍为 CPU 25% / 固定 1 GiB；预算是上限，不会预先占满，也不是操作系统硬配额。

### Buildroot / 内核独立构建目录

编译数据库模式支持显式路径映射。在工程文件管理中选择数据库，点击“添加构建目录 → 源码目录映射”，先选择编译记录中的构建目录，再选择工作区内对应的源码目录，最后点击开始索引。支持多个映射，嵌套目录按最长路径优先匹配。

例如 Buildroot 的 `output/build/linux-custom` → 打开的 `linux/linux-7.0`。插件先按记录的 `directory` 解析 `file`、`-I`、`-iquote`、`-isystem` 和 `-include`，再映射路径；读取当前源码，不使用过时的构建副本。普通 `make O=...` 如果记录已指向原始源码，则无需映射。映射不改写原始数据库，也不会改变 clangd 的配置。仅在构建目录存在的生成文件（如 `include/generated/autoconf.h`）当前不收录，会显示在缺失统计/日志中；汇编仍不属于本地 C 索引范围。
